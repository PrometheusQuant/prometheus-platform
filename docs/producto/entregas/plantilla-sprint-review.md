# Plantilla de sprint review con el cliente

Cada incremento se revisa con el profesor como **cliente**: compra el incremento con su evaluación
y decide qué sigue. Se copia este archivo a `entregas/AAAA-MM-DD-<incremento>.md` y se completa
**antes** de la reunión. Todas las cifras citan su fuente: artefacto, comando, PR o commit.

## 1. Objetivo del incremento

Una frase: qué valor recibe el cliente y cómo se nota.

## 2. Notas de entrega (en lenguaje de cliente)

Qué cambió para el usuario, no qué código se escribió. Cada punto lleva su ticket y su PR
fusionado. Se generan desde Jira (tickets en *Done* del sprint) y desde los PR fusionados en
`develop`.

## 3. Qué hace hoy el sistema

Datos reales del producto en marcha, con fecha y hora, leídos de sus registros.
